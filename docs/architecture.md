# Architecture

caps-switch is a single-process Windows application with no runtime dependencies.
It combines a low-level keyboard hook, a hidden window with a tray icon, and a small
settings store.

## Process model

```
main()
 ├─ load settings (HKCU\Software\caps-switch)
 ├─ single-instance mutex (Local\caps-switch-singleton)
 └─ run_tray()
      ├─ hidden top-level window (WS_POPUP, no HWND_MESSAGE)
      ├─ Shell_NotifyIconW(NIM_ADD)
      ├─ SetWindowsHookExW(WH_KEYBOARD_LL)
      └─ message loop (GetMessage/DispatchMessage)
```

A hidden **top-level** window is used on purpose: message-only windows do not receive
broadcast messages, and Windows broadcasts `TaskbarCreated` when Explorer restarts.
On that message the tray icon is re-added. If `NIM_ADD` fails at logon (Explorer not
ready yet), a 1-second timer retries until it succeeds.

## Key handling

`hook_proc` runs inside the message loop and must return fast: Windows removes a
low-level hook whose callback exceeds `LowLevelHooksTimeout`. The callback performs no
I/O, no allocation and no locks.

```
CapsLock down
 ├─ hook disabled            → pass through (stock CapsLock)
 ├─ Shift held (option on)   → pass through (stock caps toggle)
 ├─ already down (repeat)    → swallow
 └─ otherwise                → swallow, then emit the switch chord
CapsLock up                  → swallow (so caps state never changes)
```

The switch chord is `Alt+Shift`, `Ctrl+Shift` or `Win+Space`, depending on the selected
mode. A modifier that the user is already physically holding is **not** injected —
otherwise the synthetic key-up would release their key mid-typing.

Events injected by the application itself carry `LLKHF_INJECTED`; those are passed
through untouched, which prevents recursion.

## Fallback path

If `SendInput` fails, the app posts `WM_INPUTLANGCHANGEREQUEST` with the next layout to
the foreground window. The layout list is resolved relative to the **foreground thread**
(`GetWindowThreadProcessId` + `GetKeyboardLayout`), not the app's own thread.

Both paths are blocked by UIPI when the foreground window has a higher integrity level
(an elevated app) and caps-switch itself is not elevated. Installing the autostart as a
Task Scheduler job with *highest privileges* solves that.

## Settings

Stored per user in `HKCU\Software\caps-switch` via the Win32 Registry API
(`RegGetValueW` / `RegSetKeyValueW`) — no `reg.exe` subprocesses:

| Value | Type | Meaning |
|---|---|---|
| `Enabled` | DWORD | switching on/off |
| `ShiftCaps` | DWORD | Shift+CapsLock keeps the native caps toggle |
| `Mode` | SZ | `alt_shift` \| `ctrl_shift` \| `win_space` |
| `Language` | SZ | `auto` \| `ru` \| `en` |

Writes happen on a background thread so the menu never blocks the hook thread.

## Autostart

Two mutually exclusive options, managed by `--install` / `--install --elevated`:

1. `HKCU\...\CurrentVersion\Run` — normal privileges, starts unelevated.
2. Scheduled task `caps-switch` with trigger *at logon* and *run with highest
   privileges* — covers elevated windows, no UAC prompt at logon.

`--uninstall` removes both.

## Tray icon

The icon is a grey 3D keycap with a recessed top and two arrows. It is generated by
`tools/make-icon.ps1` into `assets/icon.ico` (16–256 px, PNG entries), embedded into the
executable with `include_bytes!`, and loaded at runtime with `CreateIconFromResourceEx`
(falling back to the stock Windows icon if anything fails).

## Localization

`src/i18n.rs` holds two static string tables (RU/EN). The language is resolved once at
start: an explicit setting (`ru`/`en`) or the system UI language
(`GetUserDefaultUILanguage`, primary language 0x19 = Russian). The tray menu is rebuilt
on every open, so a language change applies immediately.

## Packaging

- `caps-switch.exe` — the application, ~370 KB, only system DLLs.
- `caps-switch-setup-<version>.exe` — Inno Setup installer (2.2 MB) with an explicit
  install-mode dialog: *current user* (`%LOCALAPPDATA%\Programs`, HKCU autostart) or
  *all users* (`Program Files`, HKLM autostart, UAC required).
- `install.ps1` / `install.cmd` — scripted install from the latest release.
